What this demonstrates

This report is meant to show the evaluation pattern, not model performance. Each case includes a short tool trace, a resulting system state, and deterministic checks that decide whether the run should pass or fail.

Evaluation cases

Each case focuses on a simple but realistic failure mode: double refunds, ambiguous charge handling, wrong-account mutations, and correct duplicate refund resolution.
